# 연산 당구 개발 계획

작성: 2026-10-23 · 상태: 기획 완료, 구현 전 · 가칭: 연산 당구

## 목표와 확정 요구사항

당구처럼 방향과 힘을 조절해 숫자 공을 굴리고, 맞힌 공들과 연산하여 가장 큰 수를 만드는 게임이다.

- 테이블에는 숫자가 적힌 공 4~6개를 준비한다.
- 덧셈·뺄셈·곱셈·나눗셈 중 하나를 선택한다.
- 덧셈·곱셈은 작은 숫자에서, 뺄셈·나눗셈은 큰 숫자에서 출발한다.
- 사용자가 발사할 공을 선택하고 방향과 파워 게이지를 조절한다.
- `발사` 버튼을 누를 때만 공이 움직이기 시작한다.
- 공은 최대 두 번 충돌한 뒤 강제로 멈춘다.
- 최종 목표는 가능한 가장 큰 연산 결과를 만드는 것이다.

## 1차 구현 권장 규칙

아래는 요구사항의 빈 부분을 채운 제안이며, 확정 요구사항과 구분한다. 구현 착수 시 이 규칙을 기준으로 진행하고 변경 요청을 반영한다.

| 항목 | 권장안 |
|---|---|
| 공 수 | 시작 화면에서 4·5·6개 선택, 기본 5개. 발사 공도 이 수에 포함 |
| 한 판 | 같은 공 배치에서 반복 발사. 발사 후 위치와 숫자를 초기 배치로 복원하며, 최대값을 찾거나 사용자가 종료할 때까지 계속 도전 |
| 점수 | 유효 발사 중 가장 큰 결과. 충돌 0회 발사는 점수 불인정 |
| 출발 숫자 | 선택한 발사 공의 숫자가 해당 발사의 시작값 |
| 작은 수/큰 수 | 덧셈·곱셈은 최솟값 공만 발사 후보, 뺄셈·나눗셈은 최댓값 공만 발사 후보. 동률 후보는 위치를 보고 선택 가능 |
| 공 값 | 덧셈·곱셈: 시작 후보 1~3, 나머지 2~9. 뺄셈: 시작 후보 50~99, 나머지 2~20. 나눗셈: 시작 후보 60~120, 나머지 2~9 |
| 충돌 계산 | 움직이는 발사 공이 목표 공에 닿을 때 `현재값 연산 목표 공 숫자`를 즉시 적용 |
| 충돌 제한 | 목표 공과의 충돌을 최대 2회 인정. 두 번째 접촉 위치에서 즉시 정지 |
| 중복 접촉 | 같은 목표 공은 한 발사에서 한 번만 계산·충돌 횟수 인정 |
| 벽 | 반사 허용, 2회 제한에 포함하지 않음. 마찰과 최대 이동시간으로 종료 보장 |
| 목표 공 이동 | 1차 구현은 목표 공을 고정하고 발사 공만 반사·감속. 목표 공은 충돌 흔들림 연출로 타격감 제공 |
| 시간 | 조준 시간 제한 없음. 발사 후 최대 6초 또는 최소 속도 미만이면 정지 |

공을 모두 자유롭게 선택하게 하면 덧셈·곱셈에서도 가장 큰 공으로 출발하는 편이 유리하다. 그래서 시작값 조건에 맞는 공을 강조하고 그 공들 사이에서 선택하도록 제안한다. 매 배치에는 최소 두 개의 동률 발사 후보와 한 개 이상의 목표 공을 넣어 선택할 여지를 보장한다. 예: 5개 곱셈판 `[2, 2, 4, 6, 9]`, 뺄셈판 `[80, 80, 3, 8, 15]`.

첫 발사 후에도 결과를 유지해 연속 누적하면 뺄셈·나눗셈 점수가 계속 줄어든다. 매번 초기 배치에서 다시 시작하며, 가장 좋은 결과를 기록한다. 한 번 맞혔다고 판을 끝내지 않고 최대값을 찾을 때까지 다시 시도할 수 있다.

배치 생성 시 가능한 시작 공과 목표 공 1~2개의 모든 충돌 순서를 열거해 해당 배치의 이론상 최대 결과를 정확하게 계산한다. 이 값은 판정 기준으로만 쓰며 조준 중에는 공개하지 않는다. 목표 공의 배치상 실제 도달 가능성이 없는 순서는 최대값 후보에서 제외해야 하므로, 물리 시뮬레이션으로 도달 가능한 경로를 검증하거나 최대값을 달성할 수 있는 경로가 있는 배치만 생성한다. 최대값 판정이 불가능한 배치는 출제하지 않는다.

## 연산과 점수

충돌 순서 그대로 계산하며 식과 중간 결과를 함께 표시한다.

| 연산 | 예시 | 전략 |
|---|---|---|
| 덧셈 | `2 + 9 + 8 = 19` | 큰 숫자 두 개를 이어 맞히기 |
| 곱셈 | `2 × 9 × 8 = 144` | 큰 숫자 두 개로 값 키우기 |
| 뺄셈 | `80 − 3 − 8 = 69` | 작은 숫자를 맞혀 큰 값을 지키기 |
| 나눗셈 | `120 ÷ 2 ÷ 3 = 20` | 작은 제수로 큰 값을 지키기 |

- 최대 두 번은 의무 두 번이 아니다. 특히 뺄셈·나눗셈은 한 번만 맞히고 멈추는 것도 전략이다.
- 공을 한 번도 맞히지 않으면 `공을 맞혀야 기록이 생겨요` 안내와 함께 기회만 소모한다.
- 나눗셈은 0과 1을 목표 공에서 제외한다. 정수 나눗셈으로 버리지 않고 분자·분모로 정확하게 계산·비교한다.
- 나누어떨어지면 정수, 그 외에는 소수 둘째 자리까지 표시하고 필요 시 분수 원값을 함께 보여 준다. 화면 반올림값으로 순위를 판정하지 않는다.
- 뺄셈은 제안 범위에서 두 번 빼도 음수가 되지 않는다. 난이도 범위를 늘릴 때 이 조건을 다시 검증한다.
- 동일 결과는 동점으로 처리하고 시간·파워 보너스는 더하지 않는다. 수 만들기 목표를 유지한다.
- 연산별 최고 기록과 플레이 횟수를 분리한다. 4~6개 공은 선택 폭이 다르므로 공 수별 기록도 분리한다.

## 화면과 조작

진입: 게임 탭 `연산 당구` → 전용 선택 화면(연산 4개, 공 수, 규칙 안내) → 테이블 → 발사 결과 → 다음 발사 또는 최종 결과.

1. 상단에 선택 연산, 현재값, 발사 횟수, `충돌 0/2`, 이번 판 최고값을 표시한다.
2. 세로 화면 중앙에 테이블과 숫자 공을 배치한다. 발사 후보는 테두리로 강조하고 선택한 공에는 화살표를 표시한다.
3. 공을 탭해 선택한 뒤 테이블에서 드래그해 방향을 맞춘다. 공 선택이 어려운 경우를 위해 하단 후보 버튼도 제공한다.
4. 조준선은 발사 방향과 첫 예상 접촉점까지 보여 준다. 완성될 결과나 두 번째 목표까지 자동으로 풀어 주지는 않는다.
5. 하단 파워 슬라이더는 10~100%로 조절한다. 작은 화면에서도 방향 미세 조정 `좌/우` 버튼을 제공한다.
6. `발사`를 누르면 선택·조준·파워 변경을 잠근다. 움직이는 동안 현재 식·값·충돌 횟수는 즉시 갱신한다.
7. 정지하면 맞힌 공을 색과 체크로 표시하고 `2 × 9 × 8 = 144`처럼 계산 과정을 보여 준다. 최대값보다 작으면 `아쉽네요! 가장 큰 수가 아니에요. 다시 도전해 볼까요?`를 표시하고, 원한다면 어떤 공을 먼저 맞혔는지 식으로 복기한다.
8. 사용자가 `다시 도전`을 누르면 같은 배치가 복원되고 공 선택·방향·파워를 다시 조절할 수 있다. 재도전 횟수 제한은 두지 않는다.
9. 배치의 최대값을 만들면 성공 화면에 완성한 식·값·시도 횟수를 표시한다. 사용자가 `그만하기`를 누르면 현재 최고값과 시도한 식을 보여 주고 종료한다.

`발사`는 공이 선택되고 방향이 유효할 때 활성화한다. 선택 전 안내, 파워 퍼센트, 충돌 표시를 색 이외의 문자·아이콘으로도 제공한다. 백그라운드 전환 시 시뮬레이션을 멈추고 복귀 시 명시적으로 재개한다.

## 물리 처리

- 별도 물리 의존성 없이 1개 이동 공과 고정 원형 목표를 다루는 작은 순수 Dart 시뮬레이터를 우선 구현한다.
- 위치는 테이블 기준 논리 좌표로 관리하고 화면 크기에 맞춰 그린다. 공 반경과 간격을 고려하여 겹치지 않게 생성한다.
- `Ticker`의 경과시간을 고정 시간 간격으로 누적 처리한다. 긴 프레임·복귀 시 경과시간은 제한해 갑작스러운 이동을 방지한다.
- 빠른 공이 목표를 통과하지 않도록 이동 선분과 확장 원의 연속 충돌 검사를 사용한다. 한 스텝의 가장 이른 접촉을 먼저 처리한다.
- 목표 공 접촉 시 법선으로 반사하고 속도를 줄인다. 한 목표와의 중복 접촉은 계산에서 제외하며, 접촉 분리 보정으로 떨림을 막는다.
- 한 프레임에 여러 접촉이 있어도 두 번째 유효 충돌 직후 속도를 0으로 만들고 이후 접촉을 처리하지 않는다.
- 벽 반사는 네 면과 모서리를 처리하고, 마찰·최소 속도·최대 이동시간으로 무충돌 발사도 끝나게 한다.

## 기존 프로젝트 연결

- `ActionConcept.billiards`와 `/billiards-select`, `/billiards-game` 라우트를 추가한다.
- 기존 공통 액션 선택은 자릿수와 랜덤 연산을 전제로 한다. 당구는 고정 연산·공 수·전용 숫자 범위가 필요하므로 전용 선택 화면으로 분기한다.
- `billiards_select`, `billiards_game`은 기존 GetX의 view/controller/binding 구성을 따른다.
- 순수 로직 후보: `shared/billiards_physics.dart`, `shared/billiards_rules.dart`. 모델 후보: 숫자 공, 배치, 발사 결과, 분수 값.
- `ActionScoreService`는 컨셉당 정수 점수 하나를 저장하므로 분수 점수와 연산·공 수별 기록을 그대로 넣지 않는다. 프로필별 `BilliardsScoreService`를 추가하고 정확한 분자·분모와 설정을 저장한다.
- 기존 프로필 전환·삭제 처리에 새 기록 서비스를 연결한다. 일반 학습의 `GameRecord`·정답률 통계에는 합산하지 않는다.
- 효과음은 `SfxService`를 재사용하며 충돌 시 햅틱을 과도하게 중복 실행하지 않는다.

## 개발 순서

1. **규칙과 생성기** — 시작 후보, 숫자 범위, 공 배치, 연산 순서, 정확한 나눗셈 값과 비교를 구현한다. 최소 한 번 맞힐 수 있는 배치를 보장한다.
2. **시뮬레이터** — 발사 속도·마찰·벽 반사·연속 충돌·2회 정지를 구현하고 결정적인 입력으로 검증한다.
3. **조작 화면** — 공 선택·드래그 조준·방향 미세 조정·파워 슬라이더·발사 버튼과 실시간 식·충돌 표시를 연결한다.
4. **한 판 진행과 기록** — 최대값까지 반복 발사, 배치 복원, 결과 비교, 프로필별 기록 저장과 게임 탭 진입을 연결한다.
5. **화면 QA와 릴리스** — 아래 검증을 마친 후 설명 문서를 갱신한다. 마켓 빌드·버전·태그는 별도 출시 작업에서 처리한다.

## 완료 기준과 QA

- 네 연산 각각 시작값 조건과 충돌 순서가 맞고, 4·5·6개 공에서 공 선택·방향·파워·발사가 작동한다.
- 벽 반사, 무충돌 정지, 한 번 맞히고 정지, 두 번 맞힌 직후 강제 정지, 중복 접촉 무시, 고속 통과 방지를 검증한다.
- 실제 위젯 탭·드래그·슬라이더 조작으로 발사 전후 상태와 버튼 잠금을 검증한다.
- 충돌한 공의 배경색·체크, 연산식·현재값·충돌 횟수가 즉시 화면에 반영되는지 확인한다. 지연 빌더 안의 반응형 상태 읽기만으로 구독을 구성하지 않는다.
- 최대값 미달 시 안내 문구와 동일 배치 재도전, 최대값 달성 시 성공, 자발적 종료, 기록 저장, 프로필 분리, 다시하기 초기화를 검증한다.
- 최소 360×690 세로 화면 및 큰 글꼴에서 조작 영역과 숫자가 잘리지 않는지 확인한다.
- Android 실기기에서 낮은/높은 파워, 테두리 조준, 연속 두 충돌, 앱 백그라운드·복귀를 직접 플레이한다. 자동 테스트 통과와 실기기 확인을 각각 기록한다.
- `flutter analyze`, 관련 단위·위젯 테스트, Android 디버그 빌드를 통과한다.

## 범위

1차 구현은 한 기기에서 즐기는 숫자 만들기 게임이다. 목표 공도 움직이는 완전한 당구 물리, 포켓, 회전·스핀, 멀티플레이, 혼합 연산은 후속 검토로 둔다. 이번 작업은 이 계획 문서 작성이며 게임 코드는 아직 추가하지 않는다.
